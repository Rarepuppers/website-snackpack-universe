## Findings, ordered by player impact

### F1 — advertised event side effects are discarded (confirmed defect)

`dev/src/game/expedition/EncounterEventCatalog.ts:824` charges 30 Scrap for Old Sergeant's hunting mark and sets `guaranteedEliteRelicNextNode`. `applyEventResolutionToBuild` at 1755 does not carry that field. `scenes/ExpeditionEventScene.ts:195` uses that build, then saves/completes the node; only ambush is separately consumed. Source search finds hunt and echo flags in definition/resolution/result text, but no combat or persisted-run consumer. Shrine of the Hunt and Devourer's Dream also offer the hunt flag; Shrine of Echoes emits `duplicateUpgradeWithPenalty` without applying the upgrade or cooldown penalty.

Fresh browser witness `hunt`: Scrap 100 → 70, result says “next node: +elite +relic”, saved/reloaded build has no corresponding modifier. Witness `echo`: a real `rapid-cycling` upgrade remains level 1 after “Double an upgrade”, while the result says duplicate upgrade. This is a reachable production offer, not merely dead catalogue text. Recommended first fix: withhold unsupported choices while preserving event IDs, supported alternatives and Leave. Implementing persistent next-node rules is a separate content change, not necessary to stop this loss. `upgradeReroll` is also a carrier without an identified live authored offer; do not count it as another observed player defect.

### F2 — transformation purchases can consume costs for no gain (confirmed defect)

`EncounterEventCatalog.ts:1441` checks resource requirements, not transformation eligibility. At 1628, `grantTransformationAffinity` stops on rejected `applyTransformationChoice` after previous costs have already applied. `TransformationAffinity.ts:97` rejects other committed paths, apex and max rank.

Production-generated Heavy Gunner rank III is used as the fixture. Cybernetics Bay accepts “Feed it a weapon”, removes the sole rifle, but grants no Shield Lattice affinity because the path is locked. Super-Soldier Serum accepts another dose, charges 30 Scrap and 3 HP, with unchanged rank III affinity. Both persist after actual event→map→reload. This differs from completed G2: unsupported Shock-scar offers were removed; eligibility of otherwise supported event choices was not repaired. Do not reopen all transformation implementation.

### F3 — relic sacrifice does not require a relic (confirmed defect/exploit)

Designed Arrival's `offer-relic` at `EncounterEventCatalog.ts:1293` has no `minRelics` requirement. Purification without a relic is a no-op; Martyr affinity is then granted. Browser witness `free` starts with no relics and gains one affinity, saved after reload. No fabricated choice or direct effect call is necessary. Fix the authored requirement and enforce the same preflight at resolution so UI and transaction paths agree.

### F4 — result summary omits meaningful build changes (confirmed usability defect; visual observation)

`ExpeditionEventScene.ts:314` summarizes HP/shield/Scrap/XP and selected side effects, but omits weapon removal/copy, direct relic-array changes, upgrade changes and transformation changes. The inspected Cybernetics screenshot reports “You move on.” after removing a weapon. The same omission applies to supported changes; fixing F2 alone will not make result feedback truthful. Use actual before/after applied build values and catalogue display names, retain readable bounded layout and separate success from rejection. Do not replace the entire event UI with a new system.

### F5 — duplicate relic benefit is unclear (optional improvement, not a stacking defect)

Duplication Vat adds another relic ID. `content/relicCatalog.ts:242` deliberately uses a Set: duplicated Blast Baffle produces identical combat modifiers before/after. Browser `duplicate` confirms the route and persistence; production-function evidence confirms unchanged modifiers. A spare copy may be useful as a later sacrifice, so removing duplicates or enabling stacking is not justified. State that duplicates do not stack effects and may be surrendered separately; show count and actual outcome. No promised numeric combat increase exists in current wording, so this is not classified as broken combat math.

## Batch 3 independent ranked recommendations

1. **Highest-value player improvement:** make every offered event exchange honest (F1–F3). Losing a weapon or Scrap for an impossible reward harms trust more than an additional boss or decorative NPC would help.
2. **Hidden correctness risk:** partial event resolution occurs before eligibility failure, then persists. Preflight the complete transaction; never repair it by inventing stacked rewards or silently changing saved maps. Future finale work also needs persisted map policy because resume regenerates from seed.
3. **Low-risk quality of life:** actual before/after event summaries (F4) explain what happened using systems already present. This is smaller and more useful than a new tutorial mode.
4. **Small visible polish:** explicit duplicate-relic non-stacking/spare-copy wording (F5). Preserve intentional semantics; do not change balance to make a vague offer attractive.
5. **Best existing-content reuse / worthwhile medium feature:** versioned regional finales (G7), after evidence gates. Three implemented boss identities yield more value than generating another enemy family. The design already exists.
6. **Next tactical experiment:** one finite, owned teleporter stream (G8), only after the content gate and G7 stability. It offers a new decision using existing objects; activating all seven exclusions would multiply unproven scope.
7. **Larger direction:** defer a region-specific campaign with recurring NPC arcs. Current evidence supports reuse of bosses, not an expanded campaign. Reconsider only if observed runs and analytics identify repetition that G7 does not solve, with an explicit bounded region brief. No Phase 5 implementation task is justified now.
