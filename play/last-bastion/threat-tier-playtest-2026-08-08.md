# Threat-tier playable-slice observation sheet

Do not explain a modifier after the player selects it. Ask the recall questions after the run so the
test measures what the game communicated, not what the observer taught.

## Run protocol

1. Run 1: Tier 0 with onboarding forced (`?screen=game&onboarding=1`) if the save is not fresh.
2. Run 2: Tier 0 expedition clear attempt.
3. Run 3: Tier 1 after its legitimate unlock.
4. Run 4: Tier 2 after its legitimate unlock.
5. Run 5: player choice among unlocked tiers.

For each run, record the summary-screen values. The debrief identifies the tier and modifier beside
the run header and lists the top three incoming damage sources. Then ask: "Which threat tier did you
choose?" and "What changed because of that tier?" Do not count recognition prompted by the observer.

## Pass gate

- At least four of five runs start without navigation or control confusion.
- Tier is recalled correctly after at least four of five runs.
- Tier 1's elite patrol is recognized without prompting in at least two Tier 1+ runs.
- Tier 2's faster cadence is recognized without prompting in at least one Tier 2 run.
- No dominant defeat source looks unavoidable or contradicts its telegraph.
- Onboarding does not obscure threats or the upgrade decision and all four goals are understood.

If a gate fails, adjust only the failed communication or modifier before adding tiers 3–11. Preserve
the fixed threat budgets and deterministic seed contract unless the recorded evidence identifies them
as the cause.
